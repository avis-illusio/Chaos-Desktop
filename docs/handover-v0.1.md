# Chaos Desktop 交接文档

> 版本：v0.1 规格草案
> 状态：架构与核心语义已定稿，部分实现细节待确认
> 目标读者：接手本项目的开发者 / 未来的自己

---

## 1. 项目概述

Chaos Desktop 是一个从零构建的 Arch Linux Wayland 桌面壳，用于替代 KDE 系列。核心差异化：

- **平铺为主，叠层为可选实验模式**
- **全景缩放（PZ）**：屏幕放大 3 倍后的虚拟画布，通过 Dock 上的 `[PZ]` 按钮在缩略全景与局部视图间切换
- **高度图形化自定义**：任何不直接导致系统爆炸的操作都有对应 GUI 设置
- **快捷键 = 键 → 命令组文件**，命令组格式为 `.cdc`

项目以 public GitHub 仓库形式维护。

## 2. 技术栈

**全栈纯 Rust 运行时。** 不混用其他语言的运行时、解释器或脚本引擎。

| 层 | 选型 | 理由 |
|---|---|---|
| 合成器核心 | **Rust + Smithay** | 底层控制力、内存安全、参考实现（smallvil/anvil）可读 |
| Shell UI（Dock、启动器、PZ 按钮、落点指示器） | **Rust + slint** | `.slint` 描述语言编译期生成纯 Rust 代码，运行时零解释器；声明式布局和动画降低视觉 bug 风险 |
| 配置解析 / `.cdc` 解析 | **共享 Rust crate**（`cdc-parser`、配置库） | 合成器、`cdc` 可执行文件、独立设置应用三方共用 |
| X11 兼容 | **`xwayland-satellite`**（外部工具，可选依赖） | 保持合成器核心干净，X11 仅保证运行 |
| 文件管理器 | **PCManFM-Qt** | 可在 Wayland 下独立运行；注意其不提供 activation token，需合成器侧兼容 |

**取舍原则**：准确、健康、纯语种运行时优先于“容易出 bug 的美观”。slint 的 `.slint` 描述语言不是 Rust 语法，但编译产物是纯 Rust 二进制，运行时无解释器、无脚本引擎、无额外虚拟机，满足运行时纯粹性要求。

**不采用的方案**：

- PySide6 / Qt Quick 作为合成器或 Shell UI（引入 QML 引擎和 Qt Wayland 抽象层，运行时非纯 Rust；PySide6 的 Wayland `nativeInterface` 不完整）。
- 手写 `wayland-client` + `smithay-client-toolkit` 做全部 Shell UI（零框架依赖但视觉 bug 风险高，与“准确健康”优先级冲突）。

**slint 集成待验证点**：

- slint 的 Wayland 后端主要面向 `xdg-toplevel`，`wlr-layer-shell` 支持需通过 `smithay-client-toolkit` 单独创建 surface 后绑定 slint 渲染结果。第 6 阶段开始前必须验证。
- 若集成成本过高，备选：Dock 用 `smithay-client-toolkit` 手写 surface + slint 渲染，启动器走 slint 原生窗口。
- PZ 按钮过渡动画：若视口变换由合成器侧完成、Shell UI 只负责按钮状态切换，slint 动画能力足够；若按钮需跟随视口复杂形变，可能需 slint 自定义渲染回调。

## 3. 整体架构

```
┌─────────────────────────────────────────────────┐
│  合成器进程（Rust + Smithay）                     │
│  ├─ 配置服务（加载/验证/热重载/IPC 端点）          │
│  ├─ 布局引擎（可插拔 LayoutEngine trait）          │
│  ├─ cdc-parser（进程内解析 .cdc）                  │
│  └─ in-shell 面板（可选，子进程或独立线程）         │
├─────────────────────────────────────────────────┤
│  cdc 可执行文件（链接同一 cdc-parser）             │
│  ├─ cdc file.cdc  → 解析后逐条 IPC 发回合成器      │
│  └─ cdc internal ... → 单条 IPC                    │
├─────────────────────────────────────────────────┤
│  独立设置应用（链接同一配置库，Rust）              │
│  ├─ 合成器运行时：走 IPC                           │
│  └─ 合成器崩溃时：离线模式，直接读写配置文件        │
├─────────────────────────────────────────────────┤
│  Shell UI 进程（Rust + slint）                     │
│  └─ Dock、启动器、PZ 按钮、落点指示器               │
└─────────────────────────────────────────────────┘
```

**关键原则**：

- 配置读写、验证、热重载逻辑住在**合成器核心的配置服务**里，不在 in-shell 面板里。
- in-shell 和独立应用都是配置服务的客户端，**功能对等**，仅响应速度和稳定性不同。
- 用户可以禁用 in-shell，独立应用完整可用。
- Shell UI 是独立 Rust 进程，作为 Wayland 客户端连接合成器，不链接合成器核心。

## 4. 配置系统

### 4.1 Schema 驱动

- 用 Rust 结构体派生 Schema（参考 `settings-schema-rs`），Schema 同时服务于：in-shell 控件生成、独立应用控件生成、`validate` 校验。
- 验证器编译为**独立库 crate**，可离线运行（独立应用在合成器崩溃后不依赖 Wayland）。
- 配置项分级：`safe`（即时生效）/ `requires_restart`（提示 + 回滚）/ `unsafe`（默认折叠，仅配置文件暴露）。

### 4.2 include 与根源追踪

- `include "path"` 按书写顺序加载，**后加载覆盖先加载**。
- 覆盖优先级：`config_file > include > default_config`（主文件最高，default 层最底）。
- 支持 `optional = true`，缺失文件静默跳过。
- **根源追踪**：每个最终值携带 `(文件绝对路径, 位置)` 元数据，合并时逐层覆盖，最终指向最后覆盖它的来源。default 层来源标记为 `None`，GUI 修改时写入主文件。
- 用保留格式的解析器（`toml_edit` / KDL 对应库）读取每层，扁平化为 `键路径 → (值, 来源)`，按优先级合并。
- GUI 展示可折叠 `$HOME` 为 `~/`，但内部比较和写回一律用绝对路径。
- 命令组文件路径的 `include` 不支持嵌套引用（叶子节点）。

### 4.3 路径解析规则

特殊内容严格只有四个：**`/`、`..`、`$HOME`、`~`**。

解析顺序：

1. 以 `/` 开头 → 原样。
2. 以 `~/` 或裸 `~` 开头 → 替换为 `$HOME/` 或 `$HOME`。
3. 以 `$HOME/` 或裸 `$HOME` 开头 → 字面替换为实际 home 路径（不展开其他环境变量）。
4. 其他（含裸路径、`./`、`../`）→ 拼到 `$HOME/` 后面。
5. 字符串层面规范化 `.` / `..`，不解析符号链接，不依赖 cwd。

等价示例：`~/Desktop` ≡ `$HOME/Desktop` ≡ `Desktop` ≡ `/home/{实际用户名}/Desktop`。

- `~user/` 不支持展开，等价于 `~/~user/`（普通相对路径）。
- 规范化过程中补末尾 `/` 用于正确处理 `..`（中间表示），输出时按目标类型决定。
- **文件路径**（`resolve_file`）：输出无末尾 `/`。
- **目录路径**（`resolve_dir`）：输出带末尾 `/`。
- 用 newtype（`FilePath` / `DirPath`）强制区分，共享内部规范化实现。
- 规范化可能跳出 home（`~/../../etc` → `/etc`），最终路径不在 `$HOME` 下时 `validate` 给提示（不拒绝）。
- 存在性检查、符号链接、非目录段后跟 `..` 的检查放在 `validate`，不在规范化函数里。

### 4.4 命令组文件路径

- 标准快捷键配置文件：`键 → 命令组文件路径` 映射。
- 命令组文件路径按 4.3 规则解析。裸路径 `actions/terminal.cdc` 解析为 `$HOME/actions/terminal.cdc`。
- 相对路径**不**相对于配置文件目录。
- GUI 路径选择器默认扫描 `~/actions/` 和 `~/.config/chaos-desktop/actions/`，允许手动输入，保存时 home 下写 `~/...` 形式。

## 5. `.cdc` 命令格式规格

### 5.1 定位

`.cdc`（Chaos Desktop Command）是**合成器官方配置和命令的唯一格式**。所有对合成器的直接操控只能通过 `.cdc` 完成，由合成器自己解析执行，不经过 sh。

`.cdc` 是**结构化数据**（KDL 风格命令列表），不是脚本。命令类型是**封闭集合**，不存在任意 shell 语法。

### 5.2 命令类型（封闭集合）

| 类型 | 语义 | 安全等级 |
|---|---|---|
| `internal "..."` | 合成器内建命令，直接调用 API，不创建进程 | safe |
| `launch "..."` | 启动应用（合成器 spawn 或 portal 激活） | safe |
| `reveal "..."` / `c"..."` | 在文件管理器中选中路径（文件或目录均可） | safe |
| `open "..."` / `p"..."` | 打开目录（必须目录） | safe |
| `xfile "{path}"` | 执行一个文件，额外创建进程 | general |
| `cdc "{path}"` | 调用子 `.cdc` 文件 | 由子文件内容决定 |

- `c"..."`：`resolve_file` 解析，验证存在性（不要求是文件），“打开父目录并选中该条目”。指向目录时同样只选中，不打开。
- `p"..."`：`resolve_dir` 解析，验证必须是目录。`p"{path}/{file}/../"` 中 `file` 非目录 → 违规报错。
- `c"..."` 和 `p"..."` 不允许路径末尾跟内容（`c"file.txt/.."` 语法错误）。
- `.cdc` 文件**不允许**包含任意 shell 命令，需要复杂逻辑用 `.sh`。

### 5.3 缩进规则

- 缩进是**语法的一部分**（类似 Python）。
- 同层级缩进必须一致；tab 和空格不能混用；缩进跳跃报错。
- **缩进块 = 独立子 `.cdc` 文件**，内部按序执行，身份栈独立初始化，不继承父层级身份。

### 5.4 身份系统

**身份附加**：`@X` 往**当前缩进层级**附加身份 `X`。
**身份卸载**：`@X!` 从**当前缩进层级**卸载身份 `X`。

规则：

- **同级管理**：只能卸载当前层级自己附加的身份，不能操作父层级或子层级的身份。
- **一行一个身份**：`@A @B` 语法错误。
- **嵌套允许**：缩进表达层级，`!` 关闭最近一个同层级未关闭的身份。
- **卸载空身份** → 警告 + 空操作，不报错。
- **文件末尾未卸载的身份** → 提示，隐式关闭，不报错。
- **孤立 `@X!`**（当前层级无对应 `@X`）→ 警告。
- 身份命令自身也是命令，在执行序列中占据位置。

**已定义身份**：

- `@synchronizer`：并行身份。区域内（当前层级附加后）的命令**同时触发**，每条命令自己处理并发（`internal` 自管队列，`launch`/`xfile` 各自 spawn 不等待完成）。`@synchronizer!` 本身也是极快命令，与区域内其他命令同时触发，执行后切回顺序模式。

**并行块时间线示例**：

```text
@synchronizer      # t0: 切换到并行模式
  a                # t1: a 启动、b 启动、@synchronizer! 同时
  b
@synchronizer!     # t1: 切回顺序模式（极快）
c                  # t2: 顺序执行，等 c 完成
d                  # t3: 顺序执行，等 d 完成
# a、b 可能仍在后台，主序列不关心
```

并行块内 `internal` 的实际执行顺序由合成器队列决定，不保证按出现顺序。

### 5.5 `@continue`

- **位置自由**，可多次使用。
- 语义：在当前位置，把**调用点父身份快照**按序施加到当前执行单元的身份栈。
- 子文件/缩进块默认身份栈独立（空）。`@continue` 是唯一的继承入口。
- 多次 `@continue` **不去重**，每次施加快照。
- 父身份为空时 `@continue` → 等同常态启动 + 警告。
- `@continue` 施加的身份标记为 `Inherited`，子文件内 `@X!` **不能卸载** `Inherited` 条目（警告 + 空操作）。
- 快照在调用点捕获一次，不读取父文件后续变化。
- 缩进块第一行 `@continue` 和独立子文件第一行 `@continue` 等价。

### 5.6 `@no-error-output` 指令

**抑制警告，不影响错误。错误永远输出。**

语法：

- `@no-error-output` ≡ `@no-error-output{:}`：抑制后续所有命令警告，直到执行单元结束。
- `@no-error-output{N}`：抑制后续 N 条命令的警告。
- `@no-error-output{索引集合}{@type}`：抑制后续类型为 `@type` 的命令的警告，中间其他命令不受影响。
- `@no-error-output{:}{@type}`：抑制后续所有类型为 `@type` 的命令警告。

**抑制范围从指令自身开始**，指令自身若类型匹配也进入范围（`{:}{@no-error-output}` 可自抑制）。

**索引集合语法**：

| 写法 | 含义 | 越界行为 |
|---|---|---|
| `5` | 第 5 条 | 报错，终止该区间 |
| `-5` | 倒数第 5 条 | 报错，终止该区间 |
| `*5` | 第 5 条 | 回退到第 1 条 |
| `5*` | 第 5 条 | 回退到最后 1 条 |
| `*-5` | 倒数第 5 条 | 回退到第 1 条 |
| `-5*` | 倒数第 5 条 | 回退到最后 1 条 |

- `{A:B}`：取两端点之间（含端点）所有位置，**端点顺序无关**（`{3:1}` ≡ `{1:3}`）。
- `{A:B, C:D}`：多个区间取并集，去重。
- 无 `*` 的端点越界 → 报错，终止该区间，同一指令其他区间照常生效，`.cdc` 继续执行。
- 正负索引混用：负索引按 `len + index + 1` 映射，重叠按实际位置去重。
- 重复索引去重。
- 指令未匹配到任何目标 → 警告（自身可被 `{:}{@no-error-output}` 抑制）。
- 索引越界（有 `*` 回退后仍无效的情况）→ 警告。

**预扫描要求**：所有带 `:` 区间或负索引的指令需要 AST 后处理（先收集所有匹配命令，再解析索引为实际位置集合）。`cdc-parser` 输出 `suppressed_warnings: HashSet<CommandId>`，`validate` 和执行器共用，不各自解析。

## 6. `cdc` 可执行文件

- 是命令体系、格式、可执行应用程序的统称。
- `cdc file.cdc` 执行文件；`cdc internal focus-next` 执行单条。
- 链接同一 `cdc-parser` 库，与合成器解析结果一致。
- 通过环境变量（如 `$CDC_SOCKET`）找合成器 IPC socket。
- 合成器未运行时，遇到需要 IPC 的命令返回非零退出码并**停止执行后续命令**（`xfile` 等已执行的保留效果）。
- 异步区域 spawn 的子进程使用 `setsid`（或双 fork）脱离 `cdc` 进程组，避免孤儿/僵尸。
- **执行路径差异**：合成器内解析时 `internal` 直接调 API；`cdc` 可执行文件内解析时 `internal`/`launch` 通过 IPC 回合成器（`launch` 走 IPC 以便合成器关联启动上下文到窗口布局）。

## 7. `.sh` 与 `.cdc` 的关系

- `.sh` 是普通 shell 脚本，`/bin/sh` 直接执行，**不需要 CDS 解析器**（CDS 层已废弃）。
- `.sh` 回合成器的通道是**调用 `cdc` 可执行文件**：
  ```sh
  #!/bin/sh
  if [ -d ~/projects ]; then
      cdc internal focus-next
      cdc launch kitty
      cdc internal move-to-current-column
  fi
  ```
- `.cdc` 调用 `.sh` 的入口是 `xfile "path.sh"`（不阻塞，spawn 后继续）。
- 双向通道：`.cdc` → `xfile` → `.sh` → `cdc` → 合成器。不存在递归解析同一文件。
- `.sh` 标记为 general，安全模式下跳过。

## 8. 安全等级与崩溃恢复

### 8.1 安全等级

- `.cdc`：静态解析，纯 `internal`/`launch`/`reveal`/`open` 为 safe；含 `xfile` 为 general。
- `.sh`：general（无法静态判定）。
- 安全模式：跳过 general 快捷键，保留 safe `.cdc` 快捷键。

### 8.2 崩溃恢复

- 合成器注册为 systemd user service，`Restart=on-failure`。
- 连续失败超过阈值（如 2 次）→ 启动独立恢复应用，进入安全模式（忽略用户配置或加载上次快照）。
- 每次 `apply` 前自动保存带时间戳的配置快照。
- 独立应用离线模式：直接读写配置文件 + 本地验证库，不依赖 IPC。
- 独立应用在线模式：走 IPC，获取版本号，`apply` 时携带版本号，不匹配则拒绝并提示重新加载。

### 8.3 双前端

- 配置服务在合成器核心，in-shell 和独立应用都是客户端，**功能对等**。
- in-shell 默认启用，可禁用；禁用后独立应用完整可用。
- in-shell 跑在独立子进程或独立线程 + panic hook，崩溃不影响合成器核心。
- 实时预览通道：不写盘、不持久化，`apply`/`cancel` 时固化或丢弃。in-shell 进程内调用，独立应用走 IPC（低优先级可丢弃）。

## 9. 实施顺序与风险

| 阶段 | 内容 | 风险 |
|---|---|---|
| 0 | 配置系统 + 独立设置应用 + `cdc-parser` 骨架 + IPC 协议定义 | 极低（纯用户空间） |
| 1 | 合成器最小核心（启动、显示一窗口、键盘输入、退出） | 中（DRM/KMS，TTY 兜底） |
| 2 | 平铺布局引擎（可插拔 `LayoutEngine`） | 中低 |
| 3 | 配置服务接入合成器 + 崩溃回退机制 | 中（坏配置可致启动崩溃，需快照回退） |
| 4 | in-shell 面板（独立子进程，走 IPC） | 中 |
| 5 | 全景缩放（3× 画布、fractional-scale、视口插值） | 中高（视觉 bug） |
| 6 | Dock、启动器、拖拽落点（Rust + slint，`wlr-layer-shell` 锚定） | 低到中 |
| 7 | 打包与依赖策略（PKGBUILD、provides/conflicts） | 中（软链系统库是红线） |
| 8 | 叠层实验模式、动画美化 | 低 |

**红线**：

- 不软链系统库（`libwayland-server`、`libinput`、Qt 库）。卫星工具用 `provides`/`conflicts` 声明，官方仓库收录后 pacman 协调替换。
- 前六个月不设为日常桌面，在 KDE 里开发，TTY 测试合成器。

**第 6 阶段前置验证**：slint 的 Wayland 后端对 `wlr-layer-shell` 的支持方式必须在开始前验证。若集成成本过高，退回 Dock 手写 surface + slint 渲染的混合方案。

1. **slint + `wlr-layer-shell` 集成方式**：slint 原生 Wayland 后端是否可直接创建 layer-shell surface，还是必须通过 `smithay-client-toolkit` 单独创建后绑定 slint 渲染结果。第 6 阶段前验证。
2. **PZ 按钮过渡动画的归属**：视口变换由合成器侧完成、Shell UI 只切按钮状态，还是按钮需跟随视口做复杂形变（可能需要 slint 自定义渲染回调）。
3. **`.cdc` 并行块内 `internal` 的实际执行顺序**由合成器队列决定，不保证出现顺序。需在用户文档中说明。
4. **`.cdc` 中 `launch` 走 IPC 还是合成器直接 spawn**：合成器内解析时直接 spawn；`cdc` 可执行文件解析时走 IPC，以便合成器关联启动上下文。
5. **全景缩放的 XWayland 降级方案**：不支持 fractional-scale 的客户端在全景模式下显示为占位缩略图，待定。
6. **配置文件格式最终选型**：TOML vs KDL（含 `include` 和保留注释/格式的解析器）。
7. **`.cdc` 文件头的安全等级显式声明**（`# cdc-safety: builtin-only`）是否需要，以及静态分析的完备性边界。
